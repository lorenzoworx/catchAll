So the WebSocket connection streams PCM audio frames into a ring buffer, and the FastAPI backend pulls them out in real time to run inference. When the buffer underruns, we get dropouts, so we tuned the chunk size and the sample rate. The client opens a socket, sends the raw PCM payload, and the server echoes back a result over the same WebSocket. Honestly the trick was just keeping the ring buffer full and the latency under fifty milliseconds.
